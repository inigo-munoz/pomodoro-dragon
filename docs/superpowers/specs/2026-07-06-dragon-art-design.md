# Dragon Art & Animation — Design Document

**Date:** 2026-07-06
**Status:** Approved (design phase)
**Builds on:** the Pomodoro Dragon MVP (branch `feat/mvp`).

## 1. Purpose

Replace the placeholder emoji art with real, AI-generated **storybook
illustrations** and bring the app to life with subtle CSS animation. The
dragon evolving through its levels is the child's emotional reward, so the
art must feel like *one* dragon growing up, and the main dragon must feel
alive even while idle.

## 2. Scope

All art becomes images (dragons are the priority), rendered so the app can
migrate one asset at a time without breaking:

- **Dragons** — 3 levels (baby → young → adult) for the MVP dragon.
- **Foods** — apple, meat, cake.
- **UI icons** — coin, shop, settings, mute, break (phased last; emoji is
  fine there until then).

Art is generated by the user in ChatGPT / DALL·E (static PNGs). This project
provides the render layer, the animation, the asset conventions, and a
ready-to-paste prompt pack. Animated GIFs are explicitly **out of scope**
(DALL·E produces stills; animation is done in CSS — see §5).

## 3. Rendering architecture — the `art()` helper

The single most important change. Today art is interpolated as **text**
(`<span>${level.image}</span>`), which works for emoji but would print a
literal path string for an image. One small helper becomes the only code
that knows how to render art:

```
art(value, altText, fallback) → HTMLElement
  - value looks like an image path (ends in .png/.webp/.svg/.jpg)
      → returns <img src="value" alt="altText" class="art-img">
        whose onerror swaps in the emoji `fallback` (see §4)
  - otherwise (an emoji or plain string)
      → returns <span class="art-emoji">value</span>
```

Every current art site uses this helper: `mainScreen` (dragon),
`chooseDragon` (dragon), `levelUp` (dragon), `shopScreen` (food icons), and
later the nav icons.

Two properties this buys us:

1. **Gradual migration.** Swapping one emoji for one image path in
   `data/*.js` is enough; every other asset keeps working as emoji until its
   turn. No half-broken intermediate state.
2. **Fallback / robustness.** If an image is missing or fails to load, the
   `<img>` `onerror` handler replaces it with the asset's emoji fallback so
   the app never shows a broken-image icon. Data entries therefore keep an
   emoji fallback alongside the image path (see §4).

## 4. Data shape and asset organization

Files live under `public/art/` (Vite serves `public/` from the root, so they
work offline and later bundle into the Capacitor APK):

```
public/art/
  dragons/  ember-baby.png  ember-young.png  ember-adult.png
  foods/    apple.png  meat.png  cake.png
  icons/    coin.png  shop.png  settings.png  mute.png  break.png
```

Data entries carry both the image path and an emoji fallback, so the render
layer can degrade gracefully. Example evolution of a dragon level:

```js
// before
{ level: 1, xpNeeded: 0, image: '🥚' }
// after
{ level: 1, xpNeeded: 0, image: '/art/dragons/ember-baby.png', fallback: '🥚' }
```

`art(value, alt, fallback)` receives the fallback so `onerror` can use it.
The game logic never changes — it still reads `level.image`; only the render
layer and the data strings change.

**Image specs (for generation):**
- PNG, **transparent background**, square (1:1).
- Generate at 1024×1024, then downscale to ~512×512 to keep the offline
  bundle light. (A downscale/optimize step is a manual/tooling task, not app
  code.)
- Consistent framing: dragon centered, same zoom across all 3 levels, so the
  evolution reads as growth, not a camera move.

## 5. Animation (CSS only, no libraries)

Keeps the ~200-line and no-dependency constraints; animation lives in
`styles.css`, never in logic.

- **Main dragon (idle):** gentle vertical float + subtle "breathing" scale,
  infinite subtle loop — alive but not distracting.
- **Level up:** the new dragon enters with a joyful bounce plus a sparkle
  (✨) burst — the emotional payoff moment.
- **Food cards:** small bounce on tap (touch feedback).
- **Eating:** a quick scale "nom" pulse on the dragon when food is bought.
- **Accessibility:** all of the above are wrapped so `prefers-reduced-motion:
  reduce` calms/disables them.

## 6. Prompt pack

Delivered as `docs/art-prompts.md`: one copy-paste ChatGPT prompt per asset,
sharing a fixed style preamble so the whole app looks like one artist's hand:
children's storybook illustration, soft watercolor, warm friendly colors,
centered, square, plain transparent background, PNG, no text/scenery.

**Consistency technique (chain by reference):** generate level 1 first; for
level 2, feed level 1 back as a reference image and ask for "the SAME dragon,
now older/bigger"; repeat level 2 → level 3. This preserves color, shape, and
features so it reads as one dragon growing.

Transparency note: DALL·E sometimes adds a background anyway. The pack
includes the explicit transparent-background phrasing; if a background still
appears, it can be removed as a post-step (tooling assistance available).

## 7. Testing

- **`art()` helper** (unit test): returns an `<img>` with the right `src`
  for an image path; returns an emoji `<span>` for an emoji value; the
  `onerror` fallback path swaps in the emoji. This is the new logic worth
  testing.
- **Migration of existing screen tests:** `mainScreen.test.js` currently
  asserts `.dragon-art` `textContent` contains an emoji. Since level images
  may now be `<img>`, these assertions move to checking the rendered art
  element (img `src` or emoji span) via the helper's contract. Update the
  affected screen tests so they assert against `art()`'s output, not raw
  emoji text.
- Visual look of the real illustrations and the feel of the animations are
  verified by eye (with the child), not automated.

## 8. Out of scope
- Animated GIF/video assets (stills + CSS animation instead).
- Generating the images themselves (user does this in ChatGPT/DALL·E).
- New dragons/levels beyond the existing MVP dragon (that's the ambitious
  iteration).
